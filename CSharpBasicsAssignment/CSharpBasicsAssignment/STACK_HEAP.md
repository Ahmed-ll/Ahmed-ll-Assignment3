What would be different with structs?

If Order were a struct (like Point from Part C), it looks completely different:

- Structs are value types, not reference types — they live directly on the stack, not on the heap.

- Order o2 = o1; would copy the entire struct's data into a new, independent memory location — not an address.

- So o1 and o2 would be two separate boxes on the stack, each holding its own copy of OrderId, CustomerName, and IsPaid.

- Changing o2.IsPaid = true would only affect o2's own copy — o1.IsPaid would stay false.

- There would be no shared heap object and no arrows pointing to the same address — each variable is fully independent, just like Point p2 = p1; in Part C doesn't affect p1 when you modify p2. ^TSGKCAdv
